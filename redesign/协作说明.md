## 二、每天怎么用 Git

仓库已经建好了：<https://github.com/jieyingfeixue/web_development>，默认分支 `main`。

### 第一次拿代码（只做一次）

```bash
git clone https://github.com/jieyingfeixue/web_development.git
```

### 每天开工前

```bash
git pull
```

**这一条最重要。** 不拉最新代码就直接改，晚上推送一定打架。

### 改完要保存时

```bash
git add -A
git commit -m "产品页：换了首图，补了两个参数"
git push
```

### 三条注意

1. **提交说明写清楚改了哪个页面。** 别写「更新」「修改」这种，出问题查不回来。
2. **`git pull` 提示冲突，别硬推。** 把报错截图发群里，两个人一起看那几行。
3. **图片别超过 5MB。** 太大的先压一下再放进去，仓库会越来越臃肿。

## 三、字体：全站只用一种

中文用系统自带的字体，英文和数字也用同一套，不额外下载。

```css
font-family: "Microsoft YaHei", "PingFang SC", "Hiragino Sans GB", sans-serif;
```

**为什么不用好看的网络字体**：要联网下载，国内打开会慢半拍，甚至直接加载失败变成默认字体。系统自带的微软雅黑在 Windows 上、苹方在 Mac 上都是同一种观感，够用。

**规矩**：整站只允许出现这一条 `font-family`。不要给标题单独换字体。

## 四、字号：只有四档，别再自己加

| 档位 | 用在哪 | 字号 | 粗细 |
|---|---|---|---|
| 一级 | 每页最顶上那一句大标题 | 40–48px | 600 |
| 二级 | 每个板块的标题 | 26–30px | 600 |
| 三级 | 卡片、小块的标题 | 18px | 600 |
| 正文 | 说明文字 | 16px | 400 |
| 辅助 | 标签、日期、备注、英文小字 | 13px | 400 |

四档之外最多加一档「辅助小字」。**如果发现自己想写第五个字号，改成上面这五档里的一个。**

## 五、颜色：只有五个

| 用途 | 色值 | 说明 |
|---|---|---|
| 页面底色 | `#FFFFFF` | 纯白，所有浅色区块都用它 |
| 深色区块 | `#071D2C` | 首页和几个重点区块用的深蓝 |
| 正文文字 | `#111827` | 近黑，不用纯黑 |
| 次要文字 | `#6B7280` | 灰色，用于说明、日期 |
| 分隔线 | `#E5E7EB` | 极浅的灰线 |
| 强调色 | `#E4584E` | 红色，只用于很小的点缀 |

**规矩**：不要自己调色。需要新的颜色先提出来，两个人都同意再加。

## 六、背景：统一白底

- 浅色区块一律 **纯白 `#FFFFFF`**，不再用米色、米黄、淡灰。
- 深色区块一律 **`#071D2C`**。
- 整站不再出现第三种底色。

**现状提醒**：现在有些区块还是米色（`#f4f1e9`、`#f3f0e8`、`#f1eee6`、`#f8f8f6`）。按这份规范都要改成纯白。**谁负责的页面谁改。**

---

## 七、风格统一：五条小规矩

1. **圆角统一 12px**，按钮用两头全圆。
2. **卡片不要硬边框**，用一层很淡的阴影，悬停时轻微上浮。
3. **每个大板块上下留白一样**，不要这块松那块紧。
4. **标题上面留一行小英文标签**（比如 `01 / NEWS`），字号固定 13px，颜色用灰色。
5. **一屏里不要出现超过两个强调色块**。红色只做小点缀，不要大面积铺。

---

## 八、改样式的规矩（这条最重要）

`site.css` 是两个人都会动的文件，最容易打架。按下面来：

1. **只改你负责页面用到的类名。** 看到不属于自己页面的样式，别动。
2. **新样式加在文件最末尾**，前面写一行注释标名字：

```css
/* ======== 张三 · 产品页 ======== */
.product-card { ... }
```

3. **改之前先在群里说一句**「我要动 site.css 了」，改完再说一句「改好了」。
4. **两边同时改同一段，Git 会报冲突**。别硬推，找对方一起看那几行。

## 九、不能直接改的东西

| 不能改 | 原因 | 正确做法 |
|---|---|---|
| 各个 HTML 里的 `<header>` 和 `<footer>` | 会被脚本覆盖回去 | 只改 `partials/` 里的文件 |
| `partials/` 改完不跑脚本 | 页面不会更新 | 在 `redesign` 目录下跑一次 `node scripts/build-layout.mjs` |
| 别人负责的页面 | 会冲突 | 提需求，让对方改 |

`partials/` 只有我能改。改完我会跑一遍上面的命令，15 个页面会同时更新。
